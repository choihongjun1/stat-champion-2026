# Data Catalog

데이터를 코드에 사용하기 전에 이 문서에 출처, 시간 범위, 단위, 주요 변수, 사용 목적, 검증 상태를 기록한다.

상태는 `VERIFIED`, `PARTIAL`, `UNVERIFIED` 중 하나를 사용한다.

> 아래 실측 수치는 2026-09-13 데이터 audit에서 로컬 raw 파일을 직접 읽어 확인한 값이다.
> 실측 수치는 **참고용 검증 결과**이며, 이를 근거로 내린 **공식 결정**은 `DECISIONS.md`에만 기록한다.
> audit 검증 스크립트는 W1 전처리 구현 시 `outputs/audit/`로 이관하여 재현 가능하게 만든다.

## 1. 인허가 3종 (공공데이터포털, CP949)

- 파일: `data/00_raw/인허가/`
  - 일반음식점: `서울시 일반음식점 인허가 정보.csv` (537,517행) — **정정(실측 확인, 2026-09-18):
    파일명이 "식품_일반음식점.csv"로 잘못 기록되어 있었다. 실제 파일명은 위와 같다.**
  - 휴게음식점: `식품_휴게음식점.csv` (646,569행)
  - 미용업: `생활_미용업.csv` (458,647행)
- 3구(광진·마포·영등포) 필터 실측: 일반음식점 76,453 (영업 18,865 / 폐업 57,588), 휴게음식점 20,484, 미용업 13,418.
- 식별자: `관리번호` — 3구 범위에서 중복 0건(3개 파일 합산 기준으로도 0건).
- 폐업일자: 폐업 건에서 결측 0. **함정: 영업 중 행의 폐업일자가 NaN이 아닌 공백 문자열인 경우가 있어 `strip()` 후 결측 처리 필요.** 미래 날짜는 0건(과거 "3건" 보고는 공백 문자열의 오인).
- 3구 폐업 연도 분포(일반음식점): 2023년 2,500 / 2024년 2,686 / 2025년 2,932. 3업종 합산 연 약 3,800~4,500건. (초기 계획서의 14,648~16,596은 다른 집계 범위의 수치로 확인됨 — 사용 금지)
- 2026년 폐업 건수는 신고 지연으로 최근 수개월이 과소 집계됨 → 라벨 성숙 컷오프 필요(`DECISIONS.md` 참조).
- 좌표: EPSG:5174, 결측 제외 100%가 서울 범위. 결측률은 업종별 상이 — 일반음식점 10.6%, 휴게음식점 4.7%, 미용업 4.9%.
- **인코딩 함정: 일반음식점 파일은 CP949로 완전 디코딩되지 않는 바이트가 존재**(byte offset 약 3,855,938 부근에서 실제 확인) → 로딩 시 `encoding_errors` 정책 필요. 미용업·휴게음식점은 전체 파일을 청크 단위 strict 디코딩 스캔한 결과 오류 0건(실측 확인, 2026-09-18).
- **컬럼 구성·순서가 3개 파일에서 서로 다름** — 일반음식점 39열, 휴게음식점 39열, 미용업 37열
  (**정정(실측 확인, 2026-09-18): 휴게음식점을 37열로 잘못 기록했었다. 실제로는 39열이다.**)
  → 위치 기반 접근 금지, 컬럼명 매핑표 사용.
- **3구 필터 기준은 주소텍스트(지번주소/도로명주소에 구 이름 포함 여부)이며, `개방자치단체코드`
  필드 단독으로는 필터링하지 않는다.** 근거(실측 확인, 2026-09-18): `개방자치단체코드`
  기준 필터는 이 문서의 3구 실측치보다 소폭 과소 카운트된다(일반음식점 -2, 휴게음식점 -1,
  미용업 -5). 3개 파일에서 총 20건(일반음식점 8, 휴게음식점 5, 미용업 7)의 행을 직접 대조한
  결과, `개방자치단체코드` 필드 자체에 데이터 입력 오류가 있었다 — 지번주소는 명백히
  마포구/광진구/영등포구인데 코드가 다른 값이거나, 반대로 코드는 3구인데 주소가 서대문구·
  구로구·성북구·용산구·충남 논산시·인천 부평구 등 명백히 타 지역인 행이 발견됨. 주소텍스트
  매칭 결과는 3개 파일 전부에서 이 문서의 실측치(76,453/20,484/13,418)와 정확히 일치(0건
  차이) — 원 audit도 주소텍스트 기준이었던 것으로 추정된다.
- 한계: 인허가일자는 개업일 proxy(승계·양도양수 시 업력 왜곡 가능), 이전(移轉)은 식별 불가.

## 2. 소진공 상가(상권)정보 (공공데이터포털, UTF-8)

- 파일: `data/00_raw/소진공_상가정보/` — **7개 스냅샷: 202412, 202503, 202506, 202510, 202512, 202603, 202606** (간격 2~4개월, 불균일).
- 3구 행수: 79,285 → 77,828 → 77,049 → 76,898 → 76,943 → 77,083 → 80,404. 전 스냅샷 업소번호 중복 0건.
- `지번코드` = PNU 19자리. 법정동코드(10)+대지구분(1)+본번(4)+부번(4) 공식과 7개 스냅샷 전수 100% 일치. 같은 업소번호의 지번코드 변경은 0.9%로 안정적.
- 결측: 호정보·동정보 100%, 층정보 약 30%, 지점명 약 90%. → 결합 키는 PNU+정규화 상호(+좌표 보조).
- 연속 스냅샷 유지율(3구): 93.5% / 95.3% / 94.3% / 97.3% / 96.9% / 89.8%. 부활(중간 공백 후 재등장)은 전체 고유 업소번호의 0.6%.
- **202603→202606 구간 이상**: 소멸 7,845(월 2,615) + 신규 11,166(월 3,722)으로 급증. 완전 신규(이전 6개 스냅샷 부재) 11,014건. **소멸 중 30.5%(2,393건)는 동일 필지+동일 정규화 상호가 새 업소번호로 재등장 = ID 재발급/DB 정비.** 이 구간의 소멸·신규는 실제 폐업·개업으로 해석 금지.
- 인허가 폐업(3구 일반음식점, 폐업일 2025-01~2026-06, n=4,004)과의 대조 실측:
  - 소진공 매칭 성공 55.5% (영업 중 점포는 80.1% — 매칭 실패가 폐업과 상관, complete-case 금지 근거)
  - 매칭 성공분 중: 동일 관측구간 소멸 72.0% / 선행 소멸 13.9%(갭 중앙값 6개월) / 폐업 후 잔존 12.9%(중앙값 9개월, 최대 18개월) / 미확인 1.2%
- 결론: 소멸은 폐업 라벨 원천으로 부적합(커버리지·ID 오염·시점 해상도). 라벨 보조정보(`sj_status`, `sj_gap_months`)로만 사용 — `DECISIONS.md` 2026-09-13 참조.

## 3. 서울 상권분석서비스 (열린데이터광장, CP949)

- 추정매출·점포: 2021Q1~2026Q2 22개 분기 전부 존재. 상권변화지표: 36,300행 = 1,650상권 × 22분기.
- **상권코드 집합의 동일성 확인됨**: 점포·추정매출·상권변화지표 CSV에서 상권코드 1,650개가
  2021~2026 전 기간 완전 동일 (코드 추가·삭제·교체 0건 — 전수 확인).
- **미검증**: 위는 코드 집합의 동일성만 확인한 것이며, 연도별 polygon geometry(공간 경계)가
  동일하다는 검증은 아니다. 영역 shp는 단일 스냅샷만 보유하므로 2024년 표준단위구역 변경이
  경계 조정을 동반했는지는 별도 검증 대상 — 공간 조인 결과를 특정 연도 경계로 전 기간에
  적용할 때는 이 한계를 명시한다.
- 길단위인구·상주인구·직장인구·집객시설 포함. 영역 shp는 EPSG:5181 (.prj 확인).

## 4. 개별공시지가 (2024·2025·2026)

- 서울 25개구 전체, 연 약 89만 필지. 3구 약 10.9~11.0만 필지/년.
- `토지코드` = 19자리 PNU → 소진공 지번코드와 직접 조인 가능. 단 17~18자리 불량 코드가 연 약 200건 존재 → 제외+플래그.
- **시점 주의: 기준년월은 1월 1일이나 개별공시지가의 실제 결정·공시는 통상 4~5월** → feature 사용 시 available_at은 공시일 기준으로 태깅.

## 5. MDIS 소상공인실태조사 2023 (CP949)

- 40,000행 × 156열. 산업중분류 47·56·96 필터 = 5,042건, 그중 서울 474건.
- 처치: 경영_전자상거래_매출실적여부 — 실적 있음 857(17.0%) / 없음 4,185(83.0%). 매출비율은 실적군에서 90~100%에 집중.
- 결과: 경영_영업이익 결측 0%, 적자 5.5%.
- 가중치: 사업체수가중값 1종만 제공. 지역은 시도(17개)까지 — 자치구 불가, 전국 분석 + 서울 부분집합 평가.

## 6. 네이버·카카오 온라인 정보 (미수집, W1 ④)

- 블로그·카페 검색: **작성일이 존재하므로 월별 시계열로 재구성하면 과거 시점 feature로 사용 가능** — 수집 시 store_id × month 형태로 저장.
- 지역검색 등록 여부·순위, 카카오 로컬 등록 여부: 수집 시점의 현재값 → **현재 진단 표시용으로만 사용, 과거 예측 feature 사용 금지**.
- 모든 수집 레코드에 `collected_at`, `query_used` 기록 필수. 수집 후 매칭률과 함께 이 문서 갱신.
