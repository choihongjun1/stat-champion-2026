### 2-1. ER 산출물과 B-3 handoff (2026-09-19)

`python -m src.data.matching`이 생성한다 (모두 git 미추적). **ER은 `sj_status`를 만들지 않는다.**
B-3가 아래 산출물로 파생한다. 소진공 소멸은 주 폐업 라벨이 아니며 주 라벨은 인허가 `close_date`다.

| 파일 | 단위 | B-3가 쓸 컬럼 |
|---|---|---|
| `outputs/matching/license_semas_matches.parquet` | 인허가 점포 (110,347행 전체) | `store_id`, `matched`, `ambiguous`, `sj_entity_id`, `sj_store_id`(매칭 당시 후보 ID), `match_tier`, `match_confidence`, `crowded_pnu`, `name_structure`, `unmatched_reason`, `license_date`, `close_date`, `status_name` |
| `outputs/standardized/semas_entities.parquet` | 소진공 업소번호 (105,264행) | `sj_store_id`, `sj_entity_id`, `id_reissued`, `entity_n_ids`, **`entity_first_snapshot`, `entity_last_snapshot`**, `entity_latest_sj_store_id` |
| `outputs/standardized/semas_panel.parquet` | 업소번호 × 스냅샷 (545,490행) | `snapshot`, `sj_store_id` (+ 표준화 속성). `sj_entity_id`는 없으므로 entities와 `sj_store_id`로 조인 |

- **B-3는 SEMAS 존재구간·last_seen을 반드시 `sj_entity_id` 기준으로 계산한다.**
  entities의 `entity_first_snapshot`/`entity_last_snapshot`을 그대로 쓰거나, 스냅샷별 이력이 필요하면
  `panel ⋈ entities (sj_store_id)` 후 `sj_entity_id`로 묶는다.
  **업소번호 기준 `first_snapshot`/`last_snapshot`은 쓰지 않는다** — 재발급된 4,700개 업소번호가 소멸처럼 보인다.
- 재발급: unambiguous 1:1 링크만 한 entity로 묶었고(`id_reissued=True`), 재발급 전후를 다시 나누지 않는다.
  ambiguous 링크 132건은 병합하지 않았으므로 각자 별도 entity다.
- 매칭 구분: `matched=False & ambiguous=True`는 후보가 여럿이라 확정하지 않은 행, `matched=False & ambiguous=False`는
  미매칭이다. 사유는 `unmatched_reason`(예: `tier4_name_not_exact_or_contained`, `ambiguous_candidates`).
- 신뢰도: `match_confidence` high(Tier1·2) / medium(Tier3) / low(Tier4). Tier3 중 `crowded_pnu=True`(후보 51개 이상 PNU)는
  표본상 오매칭 위험이 높아 후속 단계에서 별도 sensitivity 집합으로 비교할 수 있도록 flag를 보존했다.
  ER에서는 자동 제외·강등하지 않는다 (`DECISIONS.md` 2026-09-19).
- 시점 정합: **ER은 인허가 영업기간과 entity 관측구간의 겹침을 검사하지 않으며, 겹침이 짧다는 이유로
  매칭을 미매칭으로 바꾸지 않는다.** 필요하면 B-3에서 `license_date`/`close_date`와
  `entity_first/last_snapshot`으로 `overlap_days` 같은 값을 QA/provenance로 계산할 수 있다.
  현재 매칭 중 겹침 90일 미만은 6,105건이며, SEMAS 관측이 2024-12~2026-06이라 최근 개업 점포는 겹침이
  짧게 잡히는 경계 효과가 있다. `W1_MDIS_AND_LABEL.md` §B-3의 겹침 조건(원문은 '1분기 이상')과의 차이는 **미합의**이며,
  선택지와 영향은 같은 절의 "B-3 겹침 조건 (미합의)" 표에 정리돼 있다. 기준 단위도 1분기 vs 90일로 다르다.
- 202503 스냅샷 경위도는 전량 서울 밖이라 entity 좌표·Tier4 매칭에 쓰지 않는다 (entity 좌표 출처 중 202503은 0건). 원인 검증은 §2-2.

### 2-2. 202503 스냅샷 좌표 이상 (2026-09-20 재검증, Issue #14)

재다운로드한 202503 원본으로 다시 검증했다. 좌표는 원본 `경도`·`위도` 값을 그대로 읽었다.
상세 수치·figure는 `outputs/qa/semas_202503_coord_anomaly_summary.md`(git 미추적)에 있다.

- **로컬 파일 손상 아님**: 재다운로드본(`…_20250331` 배포 묶음의 서울 파일)과 `data/00_raw`의 202503이
  바이트 단위로 동일하다 (294,546,038 bytes, SHA256 `1c3d8ee0484b0fb668b83ae4f69a83e22e77b0645b943d80d630198418031047`).
- **파싱·열 밀림 아님**: UTF-8(BOM 없음) strict decode 성공, 39열 헤더가 202506과 동일, header와 필드 수가 다른 행 0,
  경도·위도 결측·파싱 실패 0, 코드 컬럼(시도·시군구·행정동·법정동·지번코드 등) 형식이 202506과 같은 수준으로 정상.
- **스냅샷 전체의 좌표 이상**: 서울 540,516행의 좌표가 100% 서울 범위 밖이다(경도 128.05~128.47, 위도 38.32~38.59).
  서울 25개 구 모두 같다. 같은 배포 묶음의 전국 17개 시도 202503 파일도 모두 같은 방식으로 밀려 있다.
- **좌표만 이상하고 식별·주소는 정상**: 202506과 공통인 업소번호 517,639건에서 시군구·법정동·지번코드·지번주소·

  (149.9~150.2km) 떨어져 있다.
- 대조군: 202412와 202506의 공통 업소번호 499,680건은 좌표가 100% 완전히 같다. 정상 스냅샷 사이에서는 좌표가 움직이지 않는다.
- **이동 형태**: 고정 평행이동이 아니다(위도 차이가 경도와 상관계수 −0.9998). 202506 좌표의 affine 변환
  (약 150km 북동 이동 + 약 1% 늘림·기울어짐)으로 거의 완벽히 설명된다(R² ≈ 0.999999997, 잔차 약 1m 이하).
- **우리 쪽 CRS 오해 가능성 낮음**: 값이 도(degree) 단위 크기이고, 투영 좌표(EPSG:5174/5179/5181/5186의 미터)로
  재해석하면 무의미한 위치가 나와 기각했다. 같은 컬럼을 202412·202506은 경위도로 읽어 정상이다.
- **미확정**: 배포처에서 어떤 처리가 이 변환을 만들었는지는 데이터만으로 특정할 수 없다. 배포 묶음에 동봉된
  `[필독]파일열람방법.txt`에는 인코딩 안내만 있고 좌표 관련 공지는 없다. 배포처 공지·정정 이력은 확인하지 않았다.
- 주의: 밀린 좌표도 대부분 한반도 대략 범위 안에 떨어진다(시도별 포함률 강원 62%, 나머지 99~100%).
  **전국 단위 범위 검사로는 이 이상을 잡을 수 없다.** 서울 외 지역을 다룰 때는 시도별 범위 검사나
  스냅샷 간 좌표 일관성 검사가 필요하다.

## 3. 서울 상권분석서비스 (열린데이터광장, CP949)

- 추정매출·점포: 2021Q1~2026Q2 22개 분기 전부 존재. 상권변화지표: 36,300행 = 1,650상권 × 22분기.
- **상권코드 신규 등장·소멸 0건**: 모든 계열 CSV의 상권코드는 현재 영역 SHP(1,650개)와 전부 조인된다.
  **정정(실측 확인, 2026-09-23): "점포·추정매출·상권변화지표에서 상권코드 1,650개가 전 기간 완전
  동일"이라고 기록했으나, 1,650개 전 분기 존재는 점포·상권변화지표에만 해당한다.** 추정매출은 전체
  고유 코드 1,598개, 분기별 1,564~1,574개다. 코드가 바뀐 것이 아니라 해당 상권×분기의 **행이 없는** 것이다.

  **행이 없는 상권×분기는 0으로 채우지 않고 NA로 둔다** (매출 0인지 공개 제외인지 원본으로 판정 불가 — 미확정).

- 길단위인구·상주인구·직장인구·집객시설 포함. 영역 shp는 EPSG:5181 (.prj 확인).

### 3-0. 스키마 변화와 갱신 정체 계열 (2026-09-23 실측)

- **점포 컬럼명 변경**: 2021~2024 파일은 `점포_수`·`유사_업종_점포_수`, 2025_2026 파일은
  `일반_점포_수`·`전체_점포_수`를 쓴다. 전 행에서 `유사_업종_점포_수 = 점포_수 + 프랜차이즈_점포_수`,
  `전체_점포_수 = 일반_점포_수 + 프랜차이즈_점포_수`가 100% 성립한다(포털 설명도 "전체 = 일반 + 프랜차이즈"). 따라서

  | 2021~2024 | 2025~2026 |
  |---|---|
  | `점포_수` | `일반_점포_수` |
  | `유사_업종_점포_수` | `전체_점포_수` |

  이름만 보고 `점포_수`를 `전체_점포_수`에 잇지 않는다(2025Q1에 프랜차이즈분만큼 가짜 단절이 생긴다).
- **분기마다 갱신되지 않는 계열** (직전 분기와 값이 완전히 같은 상권 비율로 확인):
  - 상주인구: 2022Q4·2023Q4에만 값이 바뀌고 2024Q1 이후 동결. golmok 기준시점 표기 2023년 12월.
  - 직장인구: 2021~2024 각 Q4에만 값이 바뀌고 2025Q1 이후 동결. golmok 기준시점 표기 2024년 12월.
  - 집객시설: 22개 분기 내내 동일. golmok 기준시점 표기 2020년 12월.
  - 포털 설명: "1년 중 4분기에 한번 데이터를 업데이트하여 다음 해 1, 2, 3분기의 값이 동일".
  - 따라서 **분기 코드가 값의 실제 기준시점과 다를 수 있다.** 값의 실제 기준시점 중 golmok 표기가
    없는 구간(예: 상주인구 2022Q4 값의 생성 시점)은 미확정이다.

### 3-1. 상권 영역 shp 실측 (2026-09-19, W1 공간조인 구현 시 확인)

- 1,650개 polygon (TRDAR_CD 중복 0), Polygon 1,561 / MultiPolygon 89, empty 0.
- **invalid geometry 6건** → 코드에서 `make_valid`로 수리 후 0건. raw 파일은 수정하지 않는다.
- polygon 간 overlap(>1㎡) **50쌍** 존재(주로 관광특구↔골목상권 중첩, 최대 약 27만㎡).
  실측 결과 **50쌍 모두 대상 3구 밖**이며, 이에 따라 3구 점포의 복수 polygon 후보는 0건이다.
  서울 전체로 확장하면 ambiguity 규칙이 필요하다.
- 공간연산은 EPSG:5179로 통일한다 (인허가 좌표계와 일치). x/y는 투영좌표이며 lon/lat이 아니다.
- 보유 SHP 스냅샷: 포털 zip 수정일 **2023-10-23**, DBF 헤더 갱신일 2023-10-20. 3구 polygon 235개
  (광진 62 / 마포 77 / 영등포 96).
- **과거 판본은 존재했으나 확보 불가** (2026-09-23 조사, 열린데이터광장 OA-15560 Wayback 보존본 이력):

  | 게시 시점 | 파일 |
  |---|---|
  | 2019-11-22 | `상권영역.zip` |
  | 2022-04-22 / 2022-04-28 | `구_상권영역.zip` / `신_상권영역.zip` |
  | 2023-08-25 | `2023상권영역.zip` |
  | 2023-10-23 ~ 현재 | `서울시 상권분석서비스(영역-상권).zip` (보유본) |

  다운로드가 POST 폼 방식이라 보존본에 파일이 남아 있지 않고, 현재 포털은 최신 파일 1개만 제공한다.
  API에도 geometry 버전·이력이 없다. 확보 경로는 제공기관(서울신용보증재단 데이터분석팀) 요청뿐이다.
- 공식 설명(golmok): 발달상권·전통시장 상권은 **2022년 표준단위구역** 기준으로 재설정됐고, 골목·발달·전통시장·
  관광특구 상권의 기준시점은 **2023년 06월**이다. "2024년부터 표준단위구역으로 변경" 공지와 SHP 날짜(2023-10)
  사이의 정확한 전환 시점은 **미확정**이다.
- **historical geometry consistency는 검증 불가**다. 과거 polygon이 없어 IoU·중심점 이동·면적 차이 비교를
  수행할 수 없으며, 임의 복원·추정하지 않는다. 처리 규칙은 `DECISIONS.md` 2026-09-23.

## 4. 개별공시지가 (2024·2025·2026)

- 서울 25개구 전체, 연 약 89만 필지. 3구 약 10.9~11.0만 필지/년.
- `토지코드` = 19자리 PNU → 소진공 지번코드와 직접 조인 가능. 단 17~18자리 불량 코드가 연 약 200건 존재 → 제외+플래그.

### 4-1. 2026년 0원 필지 (2026-09-22 조사, Issue #9)

- **0원은 2026년에만 나온다.** 2024·2025는 0건. 2026 raw 339행이며, 그중 336행이 19자리 PNU다
  (나머지 3행은 강동구 고덕동의 `블럭지번` 코드 `11740102005근린000X` — 19자리 검증에서 이미 제외된다).
- **0원 필지의 92%는 직전 연도에 정상 지가가 있었다**: 339건 중 311건이 2025년 값 보유
  (중앙값 247.6만원/㎡), 309건이 2024년 값 보유. 2024·2025 어디에도 없는 신규 PNU는 28건뿐이다.
- **"신규 필지라서 아직 미평가"로 설명되지 않는다**: 2026 신규 PNU 1,782건 중 0원은 28건(1.6%)이고,
  나머지 1,754건은 정상 지가(중앙값 223.2만원/㎡)를 갖는다.
- 필지구분은 토지 310 / 임야 26 / 블럭지번 3. 법정동 단위로 몰려 있다
  (강동구 상일동 57, 노원구 상계동 48, 용산구 한남동 25, 중랑구 망우동 20, 강동구 둔촌동 17 …).
- 3구 해당 필지는 26건(마포 14, 광진 12)이며, 그중 **2개 필지가 인허가 점포 10곳과 결합**된다
  (마포구 동교동 161-15 → 6곳, 서교동 441-1 → 4곳). 두 필지 모두 2024·2025에는 정상 지가가 있었다
  (동교동 1,061만→1,119만, 서교동 828만→1,128만 원/㎡).
- **해석: 0원은 유효한 지가가 아니라 해당 연도 값이 비어 있는 상태로 본다.** 공시지가 0원은
  행정적으로 의미가 없고, 같은 필지가 직전 연도에 정상 값을 가졌기 때문이다.
- **미확정**: 0이 된 행정적 사유(공시 제외·유보, 정비사업 관련 처리 등)는 데이터만으로 특정할 수 없다.
  배포처 확인 대상이다.
- 처리: raw `land_price_{year}`는 0을 그대로 보존하고, feature용으로 0을 제외한
  `land_price_{year}_valid`와 `land_price_zero_flag`를 함께 제공한다 (`DECISIONS.md` 2026-09-22).
